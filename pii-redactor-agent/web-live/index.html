Verification method

        

          After redacting, VEIL re-runs every detector over its own output and
          compares. Anything still detectable that was not deliberately preserved
          is reported as a residual — so "clean" is a measured claim, not a
          promise.
        

        

          Tokens are recognised and skipped: VEIL_EMAIL_001 is a value
          VEIL created, not one it failed to remove.
        

        

          
One known round-trip caveat

          

            A token placed immediately after a credential-shaped key
            (password=VEIL_SECRET_001) is itself matched by the
            assignment detector. Verification skips the tool's own tokens, so it
            reports clean; a second pass over the output would flag it. Prefer
            redact or remove for credentials.

Why the engine is deterministic

        
    
          
  • Two-stage detection. A permissive regex proposes candidates; a validator (Luhn, mod-97, octet range, SSA rules) decides. That is what keeps a 16-digit order number from becoming a card.
    • 
          
  • Document-order resolution. Overlaps are settled by longest span, then confidence, then risk weight — so the winner never depends on dict ordering.
    • 
          
  • Stable masking. The same value masks to the same string in every run, because there is no random padding anywhere.
    • 
          
  • Verification is measured. The clean/dirty verdict is produced by re-scanning, not asserted.
